# 담임 일일출결 매뉴얼 반영

## 확인한 자료

사용자가 제공한 `Downloads/(고) 2026년 상반기 나이스 교무업무 고등학교용 사용자 설명서 Part1(학교업무분장, 교육과정, 학적, 개별화교육계획).pdf`.
PDF 파일 370~384쪽 / 인쇄 362~376쪽을 읽었습니다. 사용자가 지정한 370~376쪽이 파일 쪽수인지 인쇄 쪽수인지 차이가 있어 양쪽을 확인했습니다.

## 반영 규칙

| 매뉴얼 | 동작 |
|---|---|
| 인쇄 362~363 | 2022 개정의 출석인정은 조회·교시·종례에 `/`를 표시하지 않음. 담임은 조회·종례·마감·사유만 수정. |
| 364~365 | 일반 지각은 조회, 조퇴는 종례 표기. 종류·구분·사유는 출결마감구분 팝업에서 적용. |
| 366~367 사례 | 출석인정만 있으면 마감 구분 미표기/사유 기록. 미인정 지각+출석인정 결과는 미인정지각, 질병 결과+출석인정 조퇴는 질병결과로 계획. |
| 367 | 지각·조퇴·결과가 겹칠 때 학교 규정에 따른 최종 한 건을 교사가 선택. 자동 우선순위 없음. 전체 사건과 각각의 사유는 보존. |
| 368~369 | 삭제는 나이스 ‘깨끗이’/저장, 마감취소는 별도. 체크온 삭제를 나이스 삭제로 간주하지 않음. 사유는 구체적인 경위를 보관. |
| 370~372 | 실제 시간표 선행 확인, 과목 출결 교차 확인, 반별일출결마감관리 저장은 마감이라는 안내. 미기록 자동 마감 금지. |
| 374~375 | 현장실습은 사용자 요청에 따라 입력·검토 기능에서 제외. 기존 데이터는 호환성을 위해 읽을 수 있으나 자동 입력은 차단. |
| 376 | 기존 일별/기간별 변동 학생 조회와 사유 조회를 유지. |

사용자 요청에 따라 2022 개정(1·2학년) 기준으로 통일하고 교육과정 선택을 제거했습니다. 사건은 그대로 남기고 일일 최종 출결 선택을 별도 필드로 저장합니다. 변동 없음은 사용자가 실제 확인한 경우에만 선택하는 선택적 항목입니다.

## 스키마

월 파일 schemaVersion 3. 버전 1·2를 읽을 때 기존 사건·revision을 보존합니다. 신규 시간은 startSession/endSession으로 저장하며 0=조회, 1~7=교시, 8=종례입니다. 기존 startPeriod/endPeriod는 읽기 호환용으로 유지하므로 이전 8교시를 종례로 재해석하지 않습니다. 신규 저장과 자동 입력 계획은 2022 기준입니다.
날짜별 `curriculum`, `decisions`(번호→사건 ID), `noChangesConfirmed`를 추가했습니다. 이전 `practice` 필드는 기존 데이터 손실 방지를 위한 읽기 호환용입니다. 신규 입력 화면에는 없습니다. PC/PWA 모두 읽기·쓰기·충돌 비교에 이 필드를 포함합니다. 사건 변경 시 해당 최종 선택을 재검토하도록 해제합니다. 이름 필드는 클라우드 스키마에 추가하지 않았습니다.

## 자동화 구현과 한계

- `homeroom_plan.py`: 순수 입력 계획 생성. 원본 전체 사유 보존, 최종 분류, 조회/종례 목표 상태, revision 기반 검토 토큰.
- `neis/homeroom_commands.py`: 담임 메뉴/탭 진입, 학급·학년도·일자 확인, 의미 있는 열 제목으로 학생 번호 행 식별, 조회/종례 입력, 출결마감구분 팝업, 사유, 저장, 재조회 검증.
- `homeroom_service.py`: 기존 로그인·브라우저 연결을 재사용. 시작 전/저장 전/저장 후 Drive 계획 변경 여부 확인. 기존 교과 자동화와 동기화 완료 플래그는 공유하지 않음.
- PC에 ‘화면 연결 점검’과 검토 후 ‘기록 입력·저장’을 연결했습니다. 연결 점검은 출결 값을 변경하거나 저장하지 않습니다. UI가 보여준 revision과 현재 계획이 다르면 입력하지 않습니다.
- 모든 대상 행의 기존 상태를 먼저 확인합니다. 기존 내용이 다르면 덮어쓰지 않으며, 교과 교시가 바뀌면 저장 전에 중단합니다. 재조회에서 표가 갱신됐다는 증거와 값 일치를 확인해야 성공으로 처리합니다.
- **실제 담임 DOM/E2E는 미검증입니다.** 가상의 페이지에서 작동한 접근성 기반 셀렉터이며, 실제 나이스가 다른 구조이거나 학과가 복합 표시되면 안전하게 중단합니다. 임의 셀 번호/고정 좌표는 만들지 않았습니다.
- **2015 개정 분기와 현장실습 입력 UI를 제거**했습니다. 모든 자동 입력 계획에서 교과 교시는 읽기 전용이며 이전 별도 실습 기록이 발견되면 실행을 차단합니다.
- 출결마감, 반별 일괄 마감, 마감취소, ‘깨끗이’, 교과담당교사에게 전달내용 전송은 자동 실행하지 않습니다. 특히 전달내용 전송은 다른 사람에게 메시지를 보내는 별도 작업입니다.
- 진단 파일은 `%LOCALAPPDATA%/NeisSubject/tmp_homeroom_structure.json`. 역할별 요소 개수와 허용된 고정 항목명만 기록하며 학생명/사유/DOM 원문은 남기지 않습니다.

## 검증

매뉴얼 예시·중복 최종 선택·마이그레이션·동시 수정·저장 순서를 자동 테스트했습니다. 합성 HTML과 별도 headless Chrome에서 실제 Selenium 입력, 저장 후 재조회, 재실행 시 `/` 유지, 교과 교시 변경 시 중단, 출석인정 사유만 입력하는 흐름을 확인했습니다.

재현: 저장소 루트에서 `py -3.14 -m subject_teacher.scripts.check_homeroom_fixture` (설치된 Chrome 및 스크립트에 지정한 로컬 드라이버 버전 필요).
합성 화면은 `tests/fixtures/homeroom_daily.html`이며 실제 나이스/Drive 데이터에 접속하지 않습니다. 이 결과는 실나이스 검증을 대신하지 않습니다.

모바일과 설치 프로그램 운영 배포는 하지 않았습니다. 먼저 개발본의 기록·최종 검토 UI를 확인할 수 있습니다.

최종 검증(2026-09-16): 관련 Python 99개, 데스크톱 UI 47개, PWA 160개 통과. PC/PWA 빌드 성공. 360px 모바일과 PC 화면에서 저장·최종 구분·메뉴 이동 입력 유지 확인. PWA는 약 500kB 청크 크기 경고가 있으며 빌드는 성공했습니다. 기존 일부 React 테스트의 act 경고는 남아 있습니다.


## 2022 기준 입력 화면 개선

- 데스크톱과 모바일이 같은 편집 컴포넌트를 사용합니다. 학생 → 출결 종류/사유 구분 → 시간 → 사유 순서입니다.
- 종류와 구분은 단일 선택 라디오 버튼, 학생은 복수 선택 버튼입니다. 출결 종류 선택 시 학생 목록을 접고 필요하면 다시 펼칩니다.
- 시간은 조회, 1~7교시, 종례를 모두 노출합니다. PC는 9열, 모바일은 순서대로 3×3 배치입니다. 결석은 하루 전체, 지각/조퇴는 한 시점, 결과는 한 시간 또는 시작·끝 연속 범위입니다.
- 기존 교시와 신규 시간 형식 간 같은 기록 중복도 검증합니다. 8·9교시의 이전 기록을 수정하면 새 시간 선택을 요구합니다.
- [GOV.UK 라디오 버튼](https://design-system.service.gov.uk/components/radios/)과 [스코틀랜드 정부 폼 가이드](https://designsystem.gov.scot/guidance/forms/form-design)를 참고해 적은 선택지는 펼쳐 보여 주고 단일/복수 선택을 구별했습니다.
- 이번 변경 검증: Python 24개, PWA 담임 관련 16개 통과. PC/PWA 빌드 성공. 실제 브라우저에서 PC·360px 모바일 저장, 범위 선택, 메뉴 이동 시 초안 유지 확인. 합성 나이스 Selenium 저장/재조회 검증 통과. 실제 담임 권한 화면 검증과 운영 배포는 별도입니다.
