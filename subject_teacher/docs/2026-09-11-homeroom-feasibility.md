# 체크온 담임 모드 검토

2026-09-11. 범위: 기존 교과용을 보존하는 확장안 검토. 담임 자동 입력은 이번 변경에 포함하지 않습니다.

## 판단

체크온 안에 교과/담임 모드를 나누는 것이 적절합니다. 별도 설치 프로그램을 다시 만들기보다 로그인, 암호화 연결, 오프라인 저장, 기간 조회, PC 반영 진행 화면을 공유하고, 담임 기록과 나이스 입력기는 분리합니다.

강점은 나이스를 열지 않고 휴대폰에서 바로 기록하고 나중에 PC에서 여러 날짜를 검토하는 경험입니다. 최종 나이스 입력에는 학교망·접속권한·인증과 PC 브라우저가 여전히 필요합니다. 나이스 없이 나이스에 저장되는 서비스로 설명해서는 안 됩니다.

## 비교 확인

내모는 웹 서비스이며 나이스 자동 입력을 위한 Chrome 확장을 별도로 제공합니다. 따라서 서비스 전체가 크롬 확장이라는 설명은 정확하지 않습니다. 배포자 설명에는 담임용 일일출결관리, 결석·지각·조퇴·결과와 출석인정, 조회·종례·교시, 사유, 여러 날짜 순차 처리와 반영 표시 기능이 있습니다. 사용 시 내모와 나이스 탭을 열고 대상 나이스 화면을 조회하도록 안내합니다.

- 배포자 공식 설명: https://chromewebstore.google.com/detail/나이스neis-출결-자동입력-by-naemo/dipgaekcpaobajidhnbjhohkpckkhlao
- 확인일: 2026-09-11. 확인한 표시 버전 0.6.4, 수정일 2026-07-02.

따라서 ‘여러 날짜 지원’은 이미 존재하는 기능입니다. 체크온의 차별점 후보는 모바일 중심의 기록, 연결이 끊겨도 보관, 교과·담임 업무를 한 앱에서 전환, PC에서 미반영만 모아 검토하는 흐름입니다. 실제 우위는 동료 교사 사용성 검증으로 판단해야 합니다.

## 기존 코드에서 재사용할 부분

| 공유 가능 | 별도 설계 필요 |
|---|---|
| Google 인증·암호화 페어링·Drive 저장 계층 | 담임 학생별 일일 출결 모델 |
| 모바일 오프라인 큐와 재연결 흐름 | 결석·지각·조퇴·결과 및 사유 분류 UI |
| 번호 중심 명부, PC 전용 이름 표시 | 조회·종례·교시 범위와 중복 규칙 |
| 기간 조회·학급별 요약, 다중 날짜 실행 틀 | 일일출결관리(담임용) 화면 선택·입력·검증 |
| 실패 시 중단, 수정 충돌 보호 | 마감된 일자, 취소·정정, 전입·전출 처리 |

과거 안내 파일은 담임용 interface_teacher.py 재사용을 언급하지만, 현재 작업 폴더에 이 파일과 btn_commands.py는 없습니다. 존재하지 않는 코드를 이미 완성된 담임 기능으로 계산하지 않습니다. 현재 runner는 교과용 /·인정결과와 과목별 화면을 전제로 합니다.

## 권장 첫 버전

1. 화면 구분 확정(사용자 답변): 메뉴 병렬 방식. 교과 출결과 담임 출결 메뉴를 항상 함께 표시합니다. PC는 왼쪽 메뉴, 모바일은 하단 메뉴에서 각각 바로 접근합니다. 숨겨진 모드 전환은 사용하지 않습니다. 기존 교과 자료를 담임 자료로 자동 변환하지 않습니다.
2. 모바일: 우리 반 학생 → 날짜·출결 종류 → 해당 교시·사유 분류 → 저장. 교시를 선택하지 않았을 때 임의의 1교시로 채우지 않습니다.
3. 조회: 일별 학급 현황, 학생별 기간 내역, 미반영·확인 필요 모아보기.
4. PC: 대상 날짜·학생·출결 종류·교시·사유를 검토하고 반영. 학교별 필수값은 실제 화면으로 확인합니다.
5. 최초 지원 범위를 고등학교 담임의 일일출결 저장으로 한정하고, 자동 마감·서류 첨부·학적 변경은 별도 검증 후 추가합니다.

## 데이터와 안전한 전환

새 파일 namespace(예: homeroom-attendance-YYYY-MM.json), 별도 schemaVersion, 별도 UI 모델을 권장합니다. 기존 교과 absences 배열에 담임 분류를 끼워 넣으면 구버전 앱이 읽거나 덮어쓰면서 손상될 수 있습니다. 날짜·학생·교시 범위별 충돌을 정의하고, 나이스 반영 대상 snapshot과 반영 결과를 분리해야 합니다.

학생 이름은 지금처럼 클라우드에서 제외합니다. 사유에 상세 건강정보나 상담내용을 자유롭게 쓰게 만들기 전에 수집 범위·보관·삭제·학교 운영 조건을 재검토해야 합니다. 첫 버전은 필요한 분류와 최소 사유 중심으로 설계하고 서류 사진 업로드는 제외하는 편이 적절합니다.

## 출시 전 필수 검증

- 담당 학교 실제 담임 화면에서 각 유형·조회·종례·교시 선택과 저장 결과를 확인.
- 복수 사유, 이미 입력된 기록, 일부 교시 정정, 전원 출석으로 되돌리기, 마감된 일자의 처리.
- 두 날짜 이상 연속 처리 중 날짜 전환 오류가 나도 다른 날에 입력하지 않는지 검증.
- 모바일 수정과 PC 반영이 겹칠 때 기존 기록을 덮어쓰지 않는지 검증.
- 교과와 담임 모드 간 자료가 섞이지 않고 구버전 앱이 새 자료를 훼손하지 않는지 검증.

권장 순서: 이번 교과용 개선 검증 → 담임 기록·기간 조회 프로토타입 → 실제 담임 화면 매핑 및 저장 검증 → 제한된 동료 교사 시험 사용 → 배포 판단.

## 화면 명세 협의 중

- 확정: 교과·담임 메뉴 상시 병렬 노출. 계정 연결과 기본 설정은 공통.
- 제안: 담임 첫 화면은 선택 날짜의 우리 반 명단과 학생별 기록. 날짜별 현황을 첫 화면으로 둘지는 사용자 답변 대기.
- 미확정: 담임 출결 종류·사유·교시 범위·중복 처리. 담임 데이터 저장 및 나이스 입력은 아직 구현하지 않음.
