# 담임 출결 첫 버전

2026-09-14. 사용자 시안 승인과 사유 입력 요구를 반영했습니다. 개발본에 구현했으며 설치본·모바일 운영 사이트에 배포하지 않았습니다.

## 사용자 흐름

- PC 왼쪽과 모바일 하단에 담임 출결 메뉴를 교과 메뉴와 함께 표시합니다.
- 학급·명단에서 등록한 일반 학급을 선택합니다. PC는 전체 학생을 행으로 표시하며 로컬 이름을 함께 보여 줍니다. 모바일은 변동이 기록된 학생을 번호로 표시합니다.
- 날짜별 결석·지각·조퇴·결과, 질병·미인정·기타·출석인정 구분, 교시, 사유를 기록합니다.
- 결석은 하루 전체, 지각·조퇴는 해당 교시, 결과는 시작~종료 교시입니다. 교시를 임의로 채우지 않습니다.
- 사유는 출결 건별 자유 입력 필수이며 현재 앱 한도는 1,000자입니다. 이는 나이스 입력 길이를 확인한 값이 아닙니다.
- 여러 학생을 선택하면 같은 사유가 각각 저장됩니다. 이후 한 건만 수정할 수 있습니다. 동일 날짜의 지각과 조퇴는 별개 기록·사유입니다.
- 중복 기록과 하루 결석/다른 출결의 중복은 거부합니다. 미기록을 출석으로 간주하지 않으며 전원 출석 확인 버튼은 두지 않았습니다.
- 기간 내역은 사용자가 기간을 선택하고 조회합니다. 학생 번호 필터를 제공하며 최신 날짜순입니다. 현재 이름을 과거 학생의 이름으로 단정하지 않도록 기간 결과는 번호를 표시합니다.
- 개별 기록 삭제 및 학급 삭제 시 해당 학급의 과거 담임 기록 삭제를 지원합니다. 나이스 원본은 변경하지 않습니다.

## 저장과 제한

- `homeroom-YYYY-MM.json` 별도 파일, schemaVersion 1. records[날짜][학급] 아래 revision/events. 교과 출결과 분리합니다.
- 사건 필드: id, number, kind, category, reason, startPeriod, endPeriod. 이름 필드는 허용하지 않습니다. 사유에도 이름과 불필요한 건강정보를 입력하지 않도록 안내합니다.
- Drive 저장은 암호화 필수입니다. 날짜/학급 revision과 파일 ETag를 함께 비교하고 다른 학급의 병행 변경은 유지합니다.
- 응답 유실 후 같은 입력을 재시도하면 중복 쓰지 않습니다. UI도 재시도 시 사건 ID를 유지합니다.
- 첫 버전 담임 기록은 온라인 저장입니다. 교과의 오프라인 대기열과 합치지 않습니다. 실패하면 폼을 유지하며, 메뉴 이동 중에도 폼을 유지합니다. 앱 종료·새로고침 이후의 초안 복구는 지원하지 않습니다. 브라우저 종료 전 변경 경고를 등록하나 모바일 OS 강제 종료까지 보장하지 않습니다.
- 오래된 다른 기기의 기록을 조용히 덮어쓰지 않습니다. 입력을 보관하고 명시적으로 최신 기록을 다시 불러와 검토해야 합니다.
- 실제 담임 나이스 화면 확인과 자동 입력, 첨부 증빙, 일괄 기간 입력은 후속 범위입니다.

## 코드와 검증

- 공용 UI/검증: PWA `src/homeroom/`. 데스크톱은 같은 컴포넌트를 가져와 중복 구현을 피합니다. 모바일은 단독 디렉터리에서 빌드할 수 있습니다.
- PC 브리지 3개 메서드는 Drive 직렬화 대상입니다. Python 저장 검증과 모바일 저장 검증을 별도로 테스트합니다.
- PC UI 47개, PWA 156개 및 Node 서버 4개, 관련 Python 44개 통과. PC·PWA 빌드 확인.
- 합성 자료로 브라우저에서 저장·수정, 메뉴 이동 시 입력 유지, 모바일 360px 입력/메뉴를 확인했습니다. 실제 사용자 Drive나 나이스에는 테스트 자료를 쓰지 않았습니다.
- 기존 PWA Node 내장 테스트가 Vitest에 함께 수집되는 실행기 설정을 분리했습니다. 일부 기존 React 테스트의 act 경고는 남아 있지만 실패는 없습니다.
