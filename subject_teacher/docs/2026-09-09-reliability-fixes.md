# 체크온 1.0.8 안정성 수정

## 범위

1. Windows 아이콘 설정으로 인한 빈 화면·응답 없음과 설치본 시작 검증.
2. PC·모바일의 월별 출결 파일 동시 저장 보호.
3. 자동 입력한 출결과 반영 완료 표시의 일치 보장.

## 변경

- 아이콘 설정은 작업 스레드의 `shown` 대신 UI 스레드의 동기 `before_show`에서 수행합니다.
- 시작 진단은 `%LOCALAPPDATA%/NeisSubject/startup.log`에 단계와 오류 유형만 기록합니다.
  화면 및 Python API 준비가 끝나지 않으면 제한 시간 뒤 실패를 알립니다.
- `check_desktop_startup`은 별도 임시 사용자 경로에서 실제 빌드 화면을 렌더링하고 Python API를 왕복 호출합니다.
  시험 중 Google 인증·Drive 접근을 막으며, 멈추거나 비정상 종료하면 실패합니다.
- `build_release`는 모든 테스트·UI 빌드·소스/EXE 시작 검사를 통과한 실행 파일만 설치본에 넣습니다.
  입력 경로를 명시하고 EXE·설치본 해시를 manifest로 남깁니다.
- Drive의 v2 메타데이터 ETag를 내용 읽기 전후에 확인하고, 같은 ETag를 `If-Match` 조건으로 v2 미디어 PUT에 전달합니다.
  조건 실패 시 무조건 저장으로 전환하지 않습니다. v3의 버전 번호를 ETag 대신 쓰지 않습니다.
- PC는 읽은 원본과 수정본·서버 최신본을 비교합니다. 다른 수업의 수정은 병합하고 같은 수업의 충돌은 보존·차단합니다.
  삭제도 같은 보호를 적용합니다.
- 모바일은 오프라인 큐에 수정 전 기준 기록을 함께 보관합니다. 충돌 시 최신 기록과 내 기록을 비교해서 선택할 수 있습니다.
  오래된 업로드의 응답이 더 최근 초안을 완료 처리하지 않도록 저장 시각을 대조합니다.
- 자동 입력 시작 시 대상 출결을 깊은 복사로 보관하고, 완료 시 동일한 내용·확인 시각인지 검사합니다.
  읽기 이후 업로드 직전 변경도 조건부 저장이 차단합니다. 수정·삭제된 기록은 완료로 표시하지 않습니다.
- 일부 수업 실패 또는 재확인 필요가 있으면 최종 진행 상태도 오류로 표시합니다.

## 호환성과 제한

- Drive JSON의 기존 camelCase 필드와 schemaVersion 1은 유지됩니다.
  PC 기준 기록은 Pydantic PrivateAttr이고 JSON으로 직렬화되지 않습니다.
  모바일 기준 기록은 로컬 IndexedDB 큐에만 추가됩니다. 기준이 없는 구버전 대기 기록은
  최신 서버 기록과 다르면 자동 덮어쓰지 않고 비교를 요청합니다.
- 조건부 저장 보호를 위해 PC와 모바일을 함께 업데이트해야 합니다.
  기존 구버전 클라이언트가 무조건 덮어쓰는 것을 새 클라이언트만으로 차단할 수는 없습니다.
- Drive는 파일명을 고유 키로 취급하지 않습니다. 첫 월파일을 두 기기가 동시에 생성하여
  중복 파일이 생기면 두 원본을 보존하고 저장·자동 반영을 중단합니다. 임의로 하나를 선택하거나
  다른 파일을 삭제하지 않습니다. 중복 원본의 통합은 별도 확인이 필요합니다.
- 이번 변경은 일반 출결 저장·삭제·완료 표시를 보호합니다. 암호화 열쇠 재발급 같은
  전체 파일 관리 작업은 다른 기기에서 기록 중인 상태와 함께 실행하지 않아야 합니다.
- 새 설치본 생성은 공개 릴리스 게시나 모바일 운영 배포를 의미하지 않습니다.

## 검증 근거

- 최종 전체 검사: Python 200개, 데스크톱 UI 18개, 모바일 102개로 총 320개 통과.
- 소스 실행, 빌드된 EXE, 현재 PC에 1.0.8을 설치한 뒤의 EXE에서 모두 `ui_and_python_ready` 통과.
- 설치 프로그램 종료 코드 0, 설치된 EXE와 빌드 EXE의 SHA-256 일치 확인.
- 산출물: `dist/installer/CheckOn-Setup-1.0.8.exe`, `dist/installer/CheckOn-1.0.8-manifest.json`.
- 현재 PC의 기존 실행 파일은 `%LOCALAPPDATA%/NeisSubject/release-backups/before-1.0.8.exe`로 보관했습니다.
  기존 계정·키·출결 저장 파일을 삭제하지 않았습니다.
- 모바일 운영 배포와 공개 릴리스 게시는 수행하지 않았습니다. 배포 시 PC·모바일 버전을 함께 전환해야 합니다.

- 기존 소스에서 아이콘 설정 위치의 멈춤을 재현했고, 수정한 실제 시작 검사에서 `ui_and_python_ready`를 확인했습니다.
- 실제 Google Drive의 임시 시험 파일로 조건부 저장의 오래된 ETag가 HTTP 412로 거절되는 것을 확인했습니다.
- 실제 암호화된 시험 월파일을 두 클라이언트로 수정하여 서로 다른 수업의 병합과 같은 수업의 충돌 차단을 확인했습니다.
  시험 파일은 삭제했습니다. 실제 학생 출결과 NEIS에는 시험 입력하지 않았습니다.
- 회귀 테스트는 업로드 직전 경쟁, 같은 수업 충돌, 다른 수업 병합, 삭제 경쟁, 응답 유실 재시도,
  자동 입력 중 수정·삭제, UI 아이콘 이벤트, 오프라인 초안의 완료 오판 방지와 사용자 충돌 해소를 포함합니다.

관련 API 자료: [Drive v2 파일 메타데이터의 ETag](https://developers.google.com/workspace/drive/api/reference/rest/v2/files).
