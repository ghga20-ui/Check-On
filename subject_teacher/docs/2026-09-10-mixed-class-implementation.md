# 이동수업 지원 구현 기록

상태: 로컬 구현, 실제 연동 검증 대기. 배포·설치본 게시·실제 출결 변경은 수행하지 않았습니다.

## 사용 흐름

1. PC의 시간표 또는 명부 설정에서 새 수업 유형을 선택합니다. 기존 통합학급은 변경하지 않습니다.
2. 여러 반 학생이 섞인 수업을 만들고 공통 학년·수업 집단·과목을 입력합니다.
3. 학생별 원소속 반·번호를 직접 입력하거나 CSV/XLSX를 가져옵니다. 분리된 열 및 합쳐진 학번의 해석 결과를 확인·수정한 후 변경 내용을 적용합니다.
4. 암호화 연결이 완료되어야 명부를 저장할 수 있습니다. 생성한 명부의 ‘수업에 연결’을 누르고 기존 시간표 또는 담당 수업 저장 버튼으로 확정합니다.
5. 대응 버전 모바일에서 반별 묶음과 전체/반 필터로 출결을 확인합니다. 같은 번호라도 원소속 반과 학생 ID가 다르면 별개입니다.

PC와 모바일 모두 대응 버전으로 갱신한 뒤 새 이동수업을 사용해야 합니다. 기존 등록 수업의 이동수업 전환은 지원하지 않습니다.

## 데이터와 보호

- 기존 학생·시간표 계약을 유지하고 별도 암호화 `mixed-groups.json`을 사용합니다.
- 새 출결은 학생 ID와 명부 버전을 참조합니다. 기존 번호형 출결은 그대로 읽고 저장합니다. 혼합 기록이 들어간 월별 출결은 버전 2입니다.
- 명부 재가져오기는 동일 학년·반·번호의 ID와 이전 명부 이력을 보존합니다. 이름은 PC 로컬 암호화 저장소에만 두고 클라우드 직렬화에서 제거합니다.
- 오래된 명부 초안은 자동으로 새 학생에게 대응시키지 않으며 저장을 차단합니다. 과거 기록의 조회와 동기화 상태 갱신은 당시 명부를 사용합니다.
- Drive 명부와 출결은 별도 파일입니다. 완전한 다중 파일 트랜잭션은 아니며, 명부 버전을 기록하여 저장 직후 극단적인 동시 변경에도 당시 학생을 해석할 수 있게 합니다.

## 검증과 제한

Python에는 합성 명부·동일번호 분리·이력·기존 계약·암호화 차단·기존 수업 전환 금지·NEIS 사전 검사·학생별 상태 검증 테스트를 추가했습니다. PC와 모바일에도 명부 편집/가져오기 및 반 필터/복원/저장 경계 테스트를 추가하고 각 빌드를 확인합니다.

2026-09-10 실행 결과: Python 관련 회귀 195개 통과, 실제 증거 검사 1개 명시적 건너뜀. 이후 저장 모델의 버전 반영 수정 후 관련 36개 재통과. PC UI 전체 28개 통과 및 빌드 성공. 모바일 전체 116개 통과(`npm test -- --maxWorkers=2`) 및 빌드 성공. 모바일 기본 병렬 실행에서는 기존 페어링 테스트가 한 번 시간 초과하여 작업자 수를 낮춘 전체 재실행으로 확인했으며, 일부 UI 테스트에는 act 경고가 남습니다. PC 문자열 반 정보의 모바일 읽기와 재직렬화 계약도 회귀 검사에 포함했습니다.

NEIS 혼합 입력은 실제 헤더의 학년·반·번호를 모두 검사합니다. 학생 행이 없거나 중복되면 해당 수업을 변경하지 않습니다. 변경 이후 상태가 불확실하면 나머지 수업도 중단합니다. 현재 전체 행과 정확한 접근성 행 개수가 노출되는 그리드만 지원하며, 가상 스크롤·불명확한 구조는 추정 입력하지 않고 차단합니다. 이 조건이 실제 화면에 맞는지는 실검증이 필요합니다.

실제 검증 결과는 `2026-09-10-mixed-class-validation.json`에 기록하며 현재 pending입니다. 사용자가 지정한 계정·수업·날짜에서 저장·재접속·필터·정확한 NEIS 행·재실행·기존 통합학급을 확인하기 전에는 전체 완료로 판정하지 않습니다.
