# 학급·명단 UX 및 기간 출결 업데이트

## 구현 범위

데스크톱 소스와 UI 빌드를 수정했습니다. 모바일 PWA·설치본·운영 배포는 이번 작업에서 변경하지 않았습니다. 사용자가 기간 조회 위치를 데스크톱 또는 모바일로 허용했으므로, PC 검토와 일괄 반영을 한 흐름으로 묶는 데스크톱을 우선 구현했습니다.

## 학급·명단

문제: 학급 생성 위치가 시간표에 숨어 있고, 명부는 별도 메뉴에 있으며, 붙여넣기는 검증 없이 교체합니다. 학생 추가 번호는 행 수 기반이어서 삭제한 번호가 있으면 중복될 수 있습니다. 저장 실패가 진행 로그에만 남는 경로도 있습니다.

변경: ‘학급·명단’ 메뉴에서 반 범위(1-5)와 과목을 한 번에 등록하고 해당 명단으로 이동합니다. 직접 입력 시간표는 요일·교시를 함께 지정합니다. 학급 목록에 인원과 명단 필요 상태를 표시합니다. 한 반 수업/혼합수업을 분리해 일반 사용자가 혼합수업 상세 설정에 압도되지 않게 합니다.

CSV/XLSX·붙여넣기·학생 수 번호 생성은 미리보기 후 합치기/새로 채우기를 선택합니다. 합치기는 같은 번호를 갱신하며 다른 기존 학생을 보존합니다. 번호 검증, 이름 생략, 저장 중·미저장·실패 표시를 제공합니다. 명단 변경은 ‘명단 저장’으로 확정합니다. 번호만 있는 행도 UI↔Python TSV를 왕복할 수 있도록 수정했습니다.

## 출결 내역

‘출결 내역’ 메뉴와 오늘 출결의 바로가기를 추가했습니다. 시작/종료일, 이번 주·이번 달·지난달 선택, 학급별 저장 수업·결과·인정결과·미반영 요약 및 학급 필터 상세를 제공합니다. 날짜 범위를 바꾸면 이전 조회 결과에서 반영을 시작하지 못하게 합니다.

저장된 월별 출결을 범위 양끝 포함해서 읽습니다. 조회는 최대 366일이며 기록이 없는 날을 출석으로 만들지 않습니다. 결과 건수는 고유 학생 수가 아니라 학생×수업 건수입니다. 전원 출석 저장은 따로 표시합니다. 현재 명단에 없는 과거 수업도 삭제하지 않고 ‘학급 확인 필요’로 남깁니다. 혼합수업은 해당 기록의 명부 revision으로 학생의 원소속 반·번호를 표시합니다.

과거 수동 시간표에 대한 별도 snapshot 스키마는 아직 없습니다. 수동 수업 ID가 삭제되거나 과거 의미가 바뀐 경우 원래 학급·과목을 완전히 복원할 수 없으며, 확인 불가 기록은 일괄 반영에서 차단합니다. 조회는 체크온 저장 자료 기준이고 나이스 현재 상태를 실시간 조회하는 감사 화면은 아닙니다.

## 여러 날짜 반영

선택 기간의 전체 학급 미반영 수업을 최대 93일까지 처리합니다. 학급 상세 필터가 반영 범위를 좁히지 않는다는 점을 확인 화면에 명시합니다. 날짜 목록, 총 수업 수, 현재 설정의 학년도·학기를 교사가 확인한 후 시작합니다. 자동 마감은 제외합니다.

로그인은 한 번, 날짜는 오름차순입니다. 빈 날짜·반영 완료 기록은 제외합니다. 확인 화면 이후 자료가 바뀌면 시작을 거부합니다. 이후에는 출결 내용·시간표 매핑·설정·혼합명부의 snapshot을 비교하면서 본인의 반영 상태 갱신만 허용합니다. 날짜 준비 실패는 기존 화면으로 우회하지 않고 실패 처리합니다. 하루에서 실패가 나오면 이후 날짜를 처리하지 않습니다. 기존 단일 날짜 실행과 동시 실행되지 않도록 실행 잠금을 공유합니다.

## 검증 및 남은 확인

관련 Python 테스트 85개, 데스크톱 UI 테스트 33개 통과. 타입 검사 및 Vite 빌드 통과. 추가 테스트는 월 경계·기록 누락·중복 번호·번호 전용 명부·변경된 조회본·로그인 중 모바일 수정·실패 날짜 중단·날짜 선택 실패에 집중했습니다.

브라우저 미리보기에서 2학년 1~3반 등록 → 2반 선택 → 번호만 있는 5명 명단 생성 → 저장 흐름과 학급별 명단 필요 상태를 확인했습니다. 학급 관리 및 빈 기간 내역 화면을 1280×720에서 확인했습니다. 캡처는 output/playwright/에 있으며 실제 학생 자료가 아닌 미리보기 자료입니다. 실제 Drive 파일 선택/저장과 설치 앱의 네이티브 창은 이 브라우저 확인 범위에 포함하지 않습니다.

실제 학교 나이스에서 여러 날짜를 쓰는 검증과 새 설치본 검증은 아직 하지 않았습니다. 기존 사용자 자료를 임의로 나이스에 입력해 검증하지 않았으며, 배포 완료로 간주하지 않습니다. 담임 모드는 별도 검토 문서를 참고하세요.


## 두 번째 UI 검토 반영

- 일반 학급(같은 반) / 혼합학급(여러 반)을 학급 추가 대화상자에서 먼저 선택합니다.
- 학급과 학생 화면은 통합 목록 + 읽기 전용 명단이며 편집할 때만 입력칸을 표시합니다. 일반 명단 수정은 로컬 초안으로 처리하고 저장 성공 후 부모 상태에 반영합니다.
- 혼합학급 명부 저장 후 담당 수업을 함께 저장합니다. 수동 시간표는 사용자가 지정한 요일·교시만 사용합니다. 부분 실패 시 저장된 그룹 ID와 수정 번호를 보존해 중복 생성하지 않습니다.
- 시간표의 새 수업 유형 카드를 제거했습니다.
- 출결 내역은 결과·인정결과 학생의 상세 행만 학급별로 표시합니다. 저장 수업 수·총계 카드를 제거했습니다. 미기록은 출석 여부 미확인 상태를 유지합니다.
- 여러 날짜 반영은 NEIS 출결 등록의 하루 등록 / 기간 등록으로 통합했습니다.
- 담임은 교과·담임 메뉴를 항상 함께 표시하는 것으로 사용자와 합의했습니다. 첫 화면 및 기록 항목은 협의 중입니다. 담임 저장 기능은 이번에 구현하지 않았습니다.

### 공용 공개 시간표 조회

- 앱에서 API 키 입력을 제거했습니다. 운영자의 기존 키는 Vercel Production의 sensitive 환경 변수 NEIS_API_KEY에 설정했습니다. 키를 코드나 앱에 포함하지 않았습니다.

- 공개 개인정보 안내에 조회 서버의 처리 항목과 캐시를 추가했습니다.
- 배포 기반: cfb90444f32949520d373196e2376f28b9788e19. 해당 배포본에 조회 API와 안내 변경만 추가한 별도 스냅샷으로 배포했습니다.

## 후속 사용성 수정

- 사용자 입력 a / 문학과 영상으로 기존 혼합학급 무한 대기는 재현되지 않았습니다. 원인을 확정했다고 설명하지 않습니다.
- 다음 단계는 일반·혼합 모두 동기적인 로컬 화면 전환으로 변경했습니다. 일반 학급도 명단 저장 시에만 Drive에 생성하므로 다음 단계에서 서버를 기다리지 않습니다. 해당 입력으로 Windows WebView 숨김 검사 및 브라우저 진입을 확인했습니다.
- 출결 내역은 PC 로컬 명단의 이름을 연결합니다. 일반 학급은 현재 설정 학년도만, 혼합학급은 해당 명부 수정 번호의 학생 ID로 매칭합니다. 이름은 동기화 토큰과 Drive에 포함하지 않습니다.
- 날짜·학급·과목·출결·반영 상태 필터 및 이름·번호 검색, 날짜/번호/이름 정렬을 추가했습니다.
- 시간표는 자동 연결된 담당 수업 확인, 날짜별 공개 일정 조회, 모바일 주간 시간표 갱신, 기존 수업의 요일·교시 배치로 정리했습니다. 새 학급 입력칸과 중복 등록 버튼을 제거했습니다.
- 진행 기록은 두 DOM 열에 세 CSS 열을 배정해 본문이 56px에 들어가던 오류였습니다. 상태 + 나머지 폭의 본문으로 수정하고 긴 글의 줄바꿈을 설정했습니다.
- 담임 기록은 docs/2026-09-11-homeroom-recording-draft.md에서 계속 협의합니다.

## 연결 대기 및 명부 편집 후속 수정

- 사용자가 연결 복구를 확인한 뒤 읽기 검사에서 계정·설정·오늘 수업이 정상 응답했습니다. 연결 장애의 단일 원인을 확정하지 않았습니다. 초기 설정 도중 주간 시간표 갱신이 직렬화된 Drive 조회를 점유할 수 있어, 설정 → 오늘 수업 → 주간 갱신 순서로 변경했습니다. 중복 조회와 오래된 날짜 응답도 제어합니다.
- 학급 삭제는 현재 담당 수업과 시간표에서 제외하며 출결 파일을 삭제하지 않습니다. 혼합학급은 archived 상태와 기존 명부 이력을 보존합니다. 동일 수업의 새 명부를 등록할 수 있고, 반복 삭제도 안전합니다. 실제 사용자 학급을 삭제하는 검사는 하지 않았습니다.
- 명부 편집 중 학급 목록을 접어 입력 폭을 확보하고 표 내부만 스크롤합니다. 저장·취소와 열 제목이 유지됩니다. Enter 이동/행 추가 및 혼합학급의 반·번호·이름 붙여넣기를 지원합니다.
- 데스크톱 UI 46개, Python 관련 검사 70개 통과. 모바일 관련 22개 통과(기존 21개 + 삭제 명부 호환 검사 1개). 데스크톱 TypeScript/Vite 빌드 완료.
- 1280×720 브라우저에서 일반/혼합 25명과 진행 기록을 함께 표시하여 마지막 이름 입력란과 저장 버튼, 하단 안내가 가려지지 않는지 확인했습니다. 합성 명단만 사용했습니다.
- 실행 중 앱에는 재시작 후 적용됩니다. 설치본 재배포 및 모바일 운영 배포는 이번 작업에서 하지 않았습니다. 모바일의 삭제 명부 호환 변경은 다음 배포에 함께 포함해야 합니다.

## 삭제 정책·엑셀 양식·기간 조회 변경

- 사용자 요청으로 이전 보존 정책을 변경했습니다. 삭제 확인 시 해당 학급의 모든 월별 출결, 담당 수업, 시간표, 명부를 삭제합니다. 다른 학급과 나이스 원본 기록은 건드리지 않습니다. Drive 파일 목록은 페이지를 끝까지 조회합니다.
- 출결 내역에서도 학급 필터를 선택해 ‘선택 학급·전체 기록 삭제’를 실행할 수 있습니다. 기존에 제외했던 학급의 남은 기록을 정리하는 경로입니다. 조회 범위 밖 기록도 삭제한다는 영구 삭제 안내를 표시합니다. 실제 운영 데이터는 이번 검증에서 삭제하지 않았습니다.
- 일반 학급은 현재 시간표의 수동 ID와 인코딩된 나이스 수업 ID로, 혼합학급은 groupId로 일치시킵니다. 이미 시간표 매핑이 사라진 수동 ID의 ‘학급 확인 필요’ 기록은 소속을 추측해 지우지 않습니다.
- 출결 삭제를 먼저 처리하며, 오류가 나면 학급 매핑을 유지해 다시 시도할 수 있게 했습니다. 여러 Drive 파일의 변경은 단일 트랜잭션은 아니므로 오류 전 처리한 월은 이미 삭제될 수 있습니다.
